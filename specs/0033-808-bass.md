## 1. Motivation

Realize R-0033. There are three parts, each in the crate that owns its concern:

1. **The voice** (`gooz-synth`): notes in, an 808 part out.
2. **The data** (`gooz-model`): a style's plan says whether it brings a bass.
3. **The wiring** (`gooz-studio`, shell, UI): singing over trap produces an
   808 track that hits with the kick, at the sung root. The studio plays, saves
   and exports it with the voice and the drums.

## 2. Design

### 2.1 The voice — `gooz_synth::render_808`

```
notes ── playable spans (valid, in range, sorted by onset) ── mono voice ── drive ── part
                                                               │
                                one oscillator, one envelope state; each span is either
                                  fresh  → attack from 0, decay, release before its end
                                  legato → no attack: level carries on, pitch glides
```

**Spans.** A note becomes a span `{ start, end, hz }` in samples:

- `start = round(onset_secs · rate)` and `end = min(start + round(duration_secs · rate), len)`.
- A note is dropped if:
  - its frequency, onset or duration is non-finite or `≤ 0` (onset `< 0`);
  - `hz ≥ rate / 2`;
  - `start ≥ len`, or it rounds to nothing (`end ≤ start`).
- Spans are stably sorted by `start`. A later span with the same `start` as an
  earlier one replaces it, because the voice is monophonic.

**Legato.** Span `i+1` is legato when `next.start < this.end` (strictly: notes
that only touch are not legato). A legato span cuts the previous one at
`next.start` with no release. The previous span only releases when the next one
is *not* legato.

**Per sample**, with `t` the seconds since the span's start:

| | Pitch | Envelope |
|---|---|---|
| fresh | `hz` | `attack(t) · e^(−t / decay_secs)`, with `attack(t) = min(1, t / 2 ms)` |
| legato | `from · (hz / from)^(min(1, t / glide_secs))`: linear in cents, `from` being the previous span's pitch | `level₀ · e^(−t / decay_secs)`, with `level₀` the previous span's envelope at the join |

- A span that releases (the next is not legato, or it runs into `len`) is
  multiplied by `min(1, (end − i) / 5 ms)` over its last 5 ms.
- One phase accumulator runs for the whole part: `phase += τ · hz / rate`, and
  the sample is `sin(phase) · envelope`.
- With `glide_secs ≤ 0` the pitch jumps at once. That is allowed, and it is
  what `glide_secs = 0` means.

**Drive.** Last, over the whole part: `Distortion::SoftClip.apply(x, DRIVE_MAX · drive)`
with `DRIVE_MAX = 8.0`. `drive` is clamped to `0..=1`, and a non-finite drive
counts as `0`. `SoftClip` tends to the identity as its drive tends to 0 (its
own floor of `1e-3` keeps it defined), so `drive = 0` is a clean sine. `tanh` is
odd and saturating, so the odd harmonics grow with drive and the output stays
in `[−1, 1]` for input in `[−1, 1]`. The envelope never exceeds 1, so the input
never does.

**Defaults** (`Bass808::default()`), to be tuned by ear:

- `glide_secs = 0.08`
- `decay_secs = 1.2`, the long tail an 808 is known for
- `drive = 0.0`

### 2.2 Shared onsets — `gooz_synth::pattern_onsets`

The 808 must hit on *the exact sample* the kick does. `render_beat` computes
each hit's offset inline, as the bar length times `step / len`, rounded and
clamped into the bar. That arithmetic moves into one public function that
`render_beat` itself now calls:

```rust
/// The sample offsets at which `render_beat` triggers `pattern`'s hits, for
/// `bars` bars of `tempo` at `sample_rate`, in order.
pub fn pattern_onsets(pattern: &Pattern, tempo: &Tempo, bars: u32, sample_rate: u32) -> Vec<usize>
```

So the kick and the 808 share one computation and cannot drift apart.
`render_beat`'s output is unchanged (its existing tests and doctest pin it).

### 2.3 The data — `gooz_model::BassVoice`

```rust
/// A bass a style brings with it (R-0033).
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
pub enum BassVoice {
    /// A sine sub-bass with a long decay, a glide and a drive. It plays the
    /// kick lane's rhythm, at the song's root.
    #[serde(rename = "808")]
    Sub808,
}

pub struct SoundPlan {
    // … existing fields …
    /// The style's bass, if it has one. A plan saved before this field existed
    /// reads as `None`.
    #[serde(default)]
    pub bass: Option<BassVoice>,
}
```

`Preset` gains `bass: Option<BassVoice>`. Trap gets `Some(BassVoice::Sub808)`,
and corrido, metal and free get `None`. `plan_sound` copies it through. The
enum is open for the genre cards' `Tololoche` and `Tuba`.

### 2.4 The wiring — `gooz-studio`

**`BassView`** (in `view.rs`, serialized camelCase, `Serialize + Deserialize`
so the shell can hand it back for save/export):

```rust
pub struct BassView {
    pub sample_rate: u32,
    pub bars: u32,
    pub seconds: f64,
    /// The pitch the 808 plays, in Hz: the song's root in the 808's register.
    pub root_hz: f64,
    pub wave: Vec<f32>,
    pub samples: Vec<f32>,
}
```

**`bass_from_plan(plan, root_hz, bars, sample_rate) -> Option<BassView>`**
(`pub(crate)`, in a new `bass.rs`):

1. If `plan.bass` is `None`, return `None`.
2. The kick lane is the plan's `VoiceRole::Kick` voice. Its pattern is
   `Pattern::euclidean(k, n)?.rotate(r)`, the way `build_beat` builds it.
3. Take `pattern_onsets(&pattern, &plan_tempo(plan), bars, rate)`. Each onset
   becomes a note on the register root. It lasts until the next onset, and the
   last one until `len = bars · bar_samples`.
4. Render with `render_808(&notes, rate, len, &Bass808 { drive: plan.drive, ..default })`.

**`in_808_register(hz) -> f64`** folds a pitch by octaves (2:1) into
`[40, 80)` Hz: halve while `≥ 80`, double while `< 40`. `root_hz` comes from
`followed_grid`'s rule (the followed root, else `GRID_ROOT_HZ`), and both are
positive and finite.

**`Accompaniment`** gains `bass: Option<BassView>`. `accompany_take` computes
it after the track, with the same `bars` and the same rate. That is the stem
invariant, pinned by test.

**Save/export.** `build_song`, `save_session` and `export_master` each gain
`bass: Option<&BassView>`. A non-empty bass becomes a stem named `"808"`,
`StemKind::Other`, placed at bar 0 with level 1.0. The Tauri `save_session`
and `export_master` commands gain `bass: Option<BassView>`.

### 2.5 The UI

- `present()` keeps `result.bass` next to `track`, and `reset()` drops it.
- `togglePlay()` starts voice, track and bass at the same scheduled `at`, and
  stops all three.
- **One master gain.** When a styled track is present, every loop plays through
  one `GainNode` set to `1 / max(1, peak(voice + track + bass))`. This is
  export's `limit_peak`, in the browser: the three stems are the same length by
  construction, so their sum's peak is exact. Without it, a sustained 808 under
  full-scale drums and a −1 dBFS voice clips the output device, which would
  crack the sound in a way nobody asked for.
- The lanes line reads `… · 808` when there is a bass.
- `saveOrExport` sends `bass`.

## 3. Code outline

```rust
// crates/gooz-synth/src/bass.rs
pub struct Bass808 { pub glide_secs: f64, pub decay_secs: f64, pub drive: f32 }

pub fn render_808(notes: &[QuantizedNote], sample_rate: u32, len: usize, cfg: &Bass808) -> Vec<f32> {
    if sample_rate == 0 {
        return Vec::new();
    }
    let rate = f64::from(sample_rate);
    let mut out = vec![0.0; len];
    let mut voice = Voice::default(); // phase + the envelope level where the last span stopped
    let spans = playable_spans(notes, rate, len);
    for (i, span) in spans.iter().enumerate() {
        let legato = i > 0 && span.start < spans[i - 1].end;
        let stop = spans.get(i + 1).filter(|next| next.start < span.end).map_or(span.end, |next| next.start);
        let releases = stop == span.end;
        voice.play(&mut out[span.start..stop], span, legato.then(|| spans[i - 1].hz), releases, cfg, rate);
    }
    let drive = DRIVE_MAX * sanitized(cfg.drive);
    for x in &mut out {
        *x = Distortion::SoftClip.apply(*x, drive);
    }
    out
}
```

```rust
// apps/gooz-studio/src/bass.rs
pub(crate) fn bass_from_plan(plan: &SoundPlan, root_hz: f64, bars: u32, sample_rate: u32) -> Option<BassView> {
    plan.bass?;
    let kick = plan.voices.iter().find(|v| v.role == VoiceRole::Kick)?;
    let pattern = Pattern::euclidean(kick.onsets, kick.steps).ok()?.rotate(kick.rotate);
    let tempo = plan_tempo(plan);
    let len = bars as usize * bar_samples(&tempo, sample_rate);
    let hz = in_808_register(root_hz);
    let onsets = pattern_onsets(&pattern, &tempo, bars, sample_rate);
    let notes = hits_until_next(&onsets, len, hz, sample_rate);
    let samples = render_808(&notes, sample_rate, len, &Bass808 { drive: plan.drive, ..Bass808::default() });
    Some(BassView::new(sample_rate, bars, hz, samples))
}
```

## 4. Non-goals

- No bass under corrido, metal or free, in hum mode, or in describe → music
  (R-0027). The describe path can read `plan.bass` later.
- No moving bass line. The notes all sit on one root until the melody-fitting
  harmony requirement. The glide is built for it.
- No 808 controls in the UI, and no change to the trap kick.
- No real-time rendering. It is offline into a buffer, like every renderer.

## 6. Acceptance criteria mapping

| AC | Where | How it is tested |
|----|-------|------------------|
| AC1 | `render_808` | Goertzel at f vs 3f/5f at drive 0; phase continuity across adjacent spans |
| AC2 | `render_808` | Instantaneous pitch (zero-crossing period) mid-glide ≈ geometric mean; no re-attack at a legato join; touching notes re-attack |
| AC3 | `render_808` | Fresh attack starts at 0 and reaches level by 2 ms; steps at ends and joins ≤ 2× a sustained sine's steepest step |
| AC4 | `render_808` | 3rd-harmonic share monotone over a drive sweep; clearly present at 1; bounded at every drive |
| AC5 | `render_808` | Determinism; exact length; each invalid-note case; unsorted input equals sorted |
| AC6 | `plan_sound` | Trap has `Some(Sub808)`, the rest `None`; a plan JSON without `bass` reads |
| AC7 | `accompany_take` | Over trap: bass same rate/length/bars; each note onset = a kick onset from `pattern_onsets`; pitch in `[40, 80)` and an octave of the root; drive = plan's. Other styles: `None` |
| AC8 | `build_song`, UI | The song has an `"808"` stem; the mixdown contains it; the UI plays all three from one `at` behind one master gain (browser check) |
| AC9 | gates | fmt, clippy `-D warnings`, test, doc |

## 7. Decision log

| Date | Decision | Rationale |
|------|----------|-----------|
| 2026-09-27 | Glide is linear in cents over `glide_secs` | It reaches its target exactly and is testable (the midpoint is the geometric mean). "Exponential glide" in the issue means exponential in Hz, which is this. |
| 2026-09-27 | Legato keeps the envelope, does not re-attack | A slide is one note moving, not two notes. |
| 2026-09-27 | `pattern_onsets` extracted from `render_beat` | One computation for where a kick lands, so the 808 cannot drift off it. |
| 2026-09-27 | A master gain mirrors export's peak limit in the UI | Three full-level loops otherwise clip the device. Export already scales the same way. |
