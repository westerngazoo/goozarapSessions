## 1. Motivation

Realize R-0033. There are three parts, each in the crate that owns its concern:

1. **The voice** (`gooz-synth`): notes in, an 808 part out.
2. **The data** (`gooz-model`): a style's plan says whether it brings a bass.
3. **The wiring** (`gooz-studio`, shell, UI): singing over trap produces an
   808 track that hits with the kick, at the sung root. The studio plays, saves
   and exports it with the voice and the drums.

## 2. Design

### 2.1 The voice — `gooz_synth::render_808`

```rust
/// One note for the bass: only what the voice reads.
pub struct BassNote { pub hz: f64, pub onset_secs: f64, pub duration_secs: f64 }

pub struct Bass808 { pub glide_secs: f64, pub decay_secs: f64, pub drive: f32 }

pub fn render_808(notes: &[BassNote], sample_rate: u32, len: usize, cfg: &Bass808) -> Vec<f32>
```

The input type is `BassNote`, not `QuantizedNote`. The voice reads three
numbers, and a caller building 808 hits from sample offsets has no honest
`degree`, `octave`, `cents_offset` or `onset_step` to give (architect review,
finding 5).

```
notes ── spans (valid, in range, total order) ── phrases ── one oscillator ── drive ── part
```

**Spans.** Each note becomes a span `{ start, end, hz }` in samples, computed
in `f64` with no `usize` arithmetic until the numbers are known to fit:

- A note is dropped when `hz`, `onset_secs` or `duration_secs` is non-finite;
  when `hz ≤ 0`, `hz ≥ rate / 2`, `duration_secs ≤ 0` or `onset_secs < 0` (an
  onset of 0 plays); or when `start_f = round(onset_secs · rate)` is not
  `< len`.
- `end_f = min(round((onset_secs + duration_secs) · rate), len)`. Onset and end
  are each rounded from their own instant, never `start + round(duration)`, so
  a note that touches the next one in time also touches it in samples
  (finding 3).
- A span that rounds to nothing (`end ≤ start`) is dropped.
- **Total order:** spans sort by `(start, hz, end)`, using `total_cmp` for
  `hz`. Among spans with the same `start` only the last survives, which is the
  highest and then the longest. The result does not depend on the input's
  order (AC5).

**Phrases.** Span `i+1` is **legato** when `next.start < this.end`; spans that
only touch are not. A phrase is a fresh span followed by every legato span
chained to it. Where a legato span begins, it cuts the previous one. A phrase
ends at the `end` of its **last** span, even when an earlier span would have
lasted longer: the voice never goes back to a note it left.

**The envelope belongs to the phrase** (finding 2). With `τ` the seconds since
the phrase started and `e` the samples left before the phrase ends:

```
env = min(1, τ / 2 ms) · e^(−τ / decay) · min(1, e / 5 ms)
```

A legato join inside a phrase therefore changes nothing about the level, so it
cannot click, however short the notes are.

**Pitch.** A fresh span sounds at its `hz`. A legato span glides from the
voice's **current** pitch at the join (finding 9), which differs from the
previous span's `hz` if that span was cut mid-glide:

```rust
/// Pitch `t` seconds into a glide from `from` to `to`: linear in cents,
/// reaching `to` at `glide` and staying there.
fn glide_hz(from: f64, to: f64, t: f64, glide: f64) -> f64
```

This is a pure function, so it is tested exactly: at `glide / 2` it is
`√(from · to)`. `glide ≤ 0` means an immediate jump.

**Oscillator.** One phase accumulator runs for the whole part:
`phase += τ · hz / rate`, and each sample is `sin(phase) · env`.

**Drive.** Applied last, over the whole part:
`Distortion::SoftClip.apply(x, DRIVE_MAX · drive)` with `DRIVE_MAX = 8.0`.
`SoftClip` tends to the identity as its drive tends to 0, so `drive = 0` is a
clean sine. `tanh` is odd and saturating, so the odd harmonics grow with drive.
The envelope never exceeds 1, so the output stays in `[−1, 1]`.

**Sanitized settings** (finding 4, following `render.rs`'s clamp of `decay`),
applied at render time:

| Setting | Value given | Treated as |
|---------|-------------|------------|
| `glide_secs` | non-finite or `≤ 0` | an immediate jump |
| `decay_secs` | NaN or `≤ 0` | the default, 1.2 s |
| `decay_secs` | `+∞` | no decay (the AC2 test uses it) |
| `drive` | non-finite | 0 |
| `drive` | anything else | clamped to `0..=1` |

**Length.** A zero `sample_rate` returns an empty `Vec`. Otherwise the output is
exactly `len` samples. `len` is allocated as given, which is the caller's
contract, as with every other buffer size in the renderers.

**Defaults** (`Bass808::default()`), to be tuned by ear:

- `glide_secs = 0.08`
- `decay_secs = 1.2`, the long 808 tail
- `drive = 0.0`

### 2.2 Shared onsets — `gooz_synth::pattern_onsets`

The 808 must hit on the exact sample the kick does. `render_beat` computes each
hit's offset inline. That arithmetic moves into two private helpers,
`bar_len(tempo, rate)` and `step_offset(step, steps, bar_len)` (rounded, then
clamped into the bar), and one public function built on them:

```rust
/// The sample offsets at which `render_beat` triggers `pattern`'s hits, for
/// `bars` bars of `tempo` at `sample_rate`: bar by bar, step by step, so
/// non-decreasing. Empty when `bars`, `sample_rate` or the pattern is empty.
/// Two offsets can coincide on a bar shorter than its steps.
pub fn pattern_onsets(pattern: &Pattern, tempo: &Tempo, bars: u32, sample_rate: u32) -> Vec<usize>
```

`render_beat` keeps its **bar → voice → step** loop order and calls the same two
helpers, so its float summation order does not change. A **characterization test
is written before the refactor** (finding 11): `render_beat` on a fixed
three-lane config, whose rotated patterns overlap across a bar line, must
produce the same samples, bit for bit, before and after.

### 2.3 The data — `gooz_model::BassVoice`

```rust
/// A bass a style brings with it (R-0033).
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
pub enum BassVoice {
    /// A sine sub-bass with a long decay, a glide and a drive.
    #[serde(rename = "808")]
    Sub808,
}

pub struct SoundPlan {
    // … existing fields …
    /// The style's bass, if it has one. A plan saved before this field existed
    /// reads as `None`.
    #[serde(default)]
    pub bass: Option<BassVoice>,
}
```

- **Placement.** `BassVoice` is a role label like `VoiceRole`, so `gooz-model`
  stays engine-agnostic (R-0026 §4) and `gooz-synth` does not learn about it.
- **Presets.** `Preset` gains `bass: Option<BassVoice>`. Trap gets
  `Some(Sub808)`; corrido, metal and free get `None`. `plan_sound` copies it
  through.
- **Future variants.** The enum is open for the genre cards' `Tololoche` and
  `Tuba`. Every consumer matches on it **exhaustively** (finding 13), so a new
  variant fails to compile until someone decides how it sounds, instead of
  silently rendering as an 808.

### 2.4 The wiring — `gooz-studio`

**One kick pattern** (finding 10). `BeatVoiceSpec` gains
`pub fn pattern(&self) -> Result<Pattern, BeatError>`, which is
`Pattern::euclidean(onsets, steps)?.rotate(rotate)`. `build_beat` uses it, and
so does the bass, which takes the kick lane from `beat_specs_from(plan)`. Where
the kick is and where the 808 hits come from one definition.

**`BassView`** (in `view.rs`, `Serialize + Deserialize`, camelCase, so the
shell can hand it back for save/export):

```rust
pub struct BassView {
    /// Which bass this is; its stem name comes from here.
    pub voice: BassVoice,
    pub sample_rate: u32,
    pub bars: u32,
    pub seconds: f64,
    /// The pitch the bass plays, in Hz: the song's root in its register.
    pub root_hz: f64,
    pub wave: Vec<f32>,
    pub samples: Vec<f32>,
}
```

**`bass.rs`** (new, `pub(crate)`):

- `in_808_register(hz) -> Option<f64>`: folds by octaves (2:1) into
  `[40, 80)`. It is total (finding 12): a non-finite or non-positive `hz` is
  `None`, and any positive finite `hz` terminates, because each halving or
  doubling moves it one octave toward the band.
- `hits_until_next(onsets, len, hz, rate) -> Vec<BassNote>`: one note per
  onset, lasting until the next onset. The last lasts until `len`, and a
  duplicate onset yields a note that rounds to nothing, which the voice drops.
  Onsets and durations are `offset / rate`, so `round(onset · rate) == offset`
  exactly (the round trip is exact far beyond any real length).
- `bass_from_plan(plan, root_hz, bars, rate) -> Option<BassView>`: an
  exhaustive `match plan.bass`. `None` returns `None`. `Some(Sub808)` takes the
  kick lane's pattern, `pattern_onsets` at `plan_tempo(plan)`, and
  `len = bars · bar_samples`, then renders
  `render_808(&hits_until_next(…), rate, len, &Bass808 { drive: plan.drive, ..default })`.

**`accompany_take`** passes `grid.root_hz()`, from the `followed_grid` it
already builds. `PitchGrid` guarantees a positive, finite root and already
holds the fallback. `Accompaniment` gains `bass: Option<BassView>` and
`levels: PlaybackLevels` (§2.5).

**Save/export** (finding 18). `build_song`, `save_session` and
`export_master` each gain `bass: Option<&BassView>`:

- A non-empty bass is the third stem, after the voice and the drums. It is
  named by its voice (`Sub808` → `"808"`, so export writes `02-808.wav`),
  `StemKind::Other`, placed at bar 0 with level 1.0.
- `span_bars` includes it.
- The Tauri `save_session` and `export_master` commands gain
  `bass: Option<BassView>`.
- The stem levels (voice 1.0, drums 0.9, bass 1.0) become named constants,
  shared with §2.5.

### 2.5 Playing it: levels from Rust, routing in the UI

**`PlaybackLevels`** (owner decision: *"ganancia maestra, como el export"*,
finding 16). The audio math lives in Rust, where the gates test it:

```rust
/// The gain each track plays at so the browser hears what export writes:
/// each track's export level, times one shared scale that is below 1 only
/// when their sum would pass full scale.
pub struct PlaybackLevels { pub voice: f32, pub track: f32, pub bass: f32 }

pub(crate) fn playback_levels(voice: &[f32], track: &[f32], bass: Option<&[f32]>) -> PlaybackLevels
```

- **How it is computed.** `scale = 1 / max(1, peak(Σ level_i · stem_i))`, with
  the same levels `build_song` places: voice 1.0, drums 0.9, bass 1.0. Each
  field is `level_i · scale`. The stems are equal in length by construction
  (R-0042), so the sum is exact.
- **What pins it.** A test requires `Σ levels_i · stem_i` to equal
  `build_song(…).mixdown()` sample for sample, within f32 rounding, for trap
  (with bass) and for corrido (without).
- **Where it applies.** Every styled result carries it, so corrido, metal and
  free stop clipping too. That is part of the owner's decision.

**UI** (findings 16d, 17):

- **Result state.** `present()` sets `bass = result.bass ?? null` and
  `levels = result.levels` in the style branch, and `bass = null`,
  `levels = null` in the other branch. `reset()` clears both.
- **Routing.** A styled play creates one `GainNode` per track, set from
  `levels`. The voice, track and bass sources connect through them to the
  destination and start at the same `at`. `startBeatNode` takes the node to
  connect to, so the beat builder's generic beat keeps going straight to the
  destination, unchanged.
- **Stopping.** Both `stopAudio` and `stopBeat` stop the bass node.
- **Display and save.** The lanes line reads `… · 808` when there is a bass,
  and `saveOrExport` sends `bass`.

## 3. Code outline

```rust
// crates/gooz-synth/src/bass.rs
pub fn render_808(notes: &[BassNote], sample_rate: u32, len: usize, cfg: &Bass808) -> Vec<f32> {
    if sample_rate == 0 {
        return Vec::new();
    }
    let rate = f64::from(sample_rate);
    let settings = Settings::from(cfg);                  // sanitized glide / decay / drive
    let mut out = vec![0.0; len];
    let mut osc = Oscillator::default();                 // one phase for the whole part
    for phrase in phrases(&spans(notes, rate, len)) {    // fresh span + its legato chain
        osc.play(&mut out, &phrase, &settings, rate);    // phrase envelope; glide from osc.hz()
    }
    for x in &mut out {
        *x = Distortion::SoftClip.apply(*x, DRIVE_MAX * settings.drive);
    }
    out
}
```

```rust
// apps/gooz-studio/src/bass.rs
pub(crate) fn bass_from_plan(plan: &SoundPlan, root_hz: f64, bars: u32, rate: u32) -> Option<BassView> {
    match plan.bass? {
        BassVoice::Sub808 => {
            let kick = beat_specs_from(plan).into_iter().find(|s| s.kind == DrumKind::Kick)?;
            let tempo = plan_tempo(plan);
            let len = bars as usize * bar_samples(&tempo, rate);
            let hz = in_808_register(root_hz)?;
            let onsets = pattern_onsets(&kick.pattern().ok()?, &tempo, bars, rate);
            let cfg = Bass808 { drive: plan.drive, ..Bass808::default() };
            let samples = render_808(&hits_until_next(&onsets, len, hz, rate), rate, len, &cfg);
            Some(BassView::new(BassVoice::Sub808, rate, bars, hz, samples))
        }
    }
}
```

## 4. Non-goals

- No bass under corrido, metal or free, in hum mode, or in describe → music
  (R-0027). The describe path can read `plan.bass` later.
- No moving bass line. The notes all sit on one root until the melody-fitting
  harmony requirement. The glide is built for it.
- No 808 controls in the UI, and no change to the trap kick.
- No real-time rendering. It is offline into a buffer, like every renderer.
- The describe path's `DescribedSong.plan` will say `bass: "808"` for a trap
  description while nothing renders it there. R-0029 must not show a planned
  bass as playing.
- No tracks collection. Each new track adds a parameter to `build_song`, the
  session commands and the UI. The studio-view requirement that follows
  replaces that with a collection, and the tololoche and tuba should make "the
  bass follows the kick" data in the plan, not a rule in the studio.

## 6. Acceptance criteria mapping

| AC | Where | How it is tested |
|----|-------|------------------|
| AC1 | `render_808` | At drive 0, one long note: Goertzel power at f against 3f and 5f. Phase continuity: adjacent fresh phrases sampled against one analytic sine |
| AC2 | `glide_hz`, `render_808` | `glide_hz` exact: `√(from·to)` at glide/2, `to` from glide on, a jump for `glide ≤ 0`. Audio at 200→400 Hz with a 0.5 s glide and `decay = +∞`: zero-crossing periods in windows track the law; no level change at the join; touching notes re-attack (a zero sample at the second onset); a note cut mid-glide starts the next glide from the current pitch, not the previous target |
| AC3 | `render_808` | A phrase's first sample is 0, and it is at full level (times decay) by 2 ms. Across attacks, releases and joins, for pitches from 40 to 80 Hz at 16, 44.1 and 48 kHz, no step exceeds 3× `2π·f_max/rate`. Control: the same render with the release factor removed exceeds it. Short legato notes (< 5 ms) inside a phrase do not click |
| AC4 | `render_808` | Steady-state H3/H1 power, drive from 0 to 1 in steps of 0.1: never falls; at 1 it is ≥ −20 dB; at 0 it is ≤ −60 dB. Bounded at every drive, including extreme and non-finite settings |
| AC5 | `render_808` | Same input twice is equal. Shuffled input equals sorted input. Exact length, and a zero rate gives an empty part. One case per invalid note (onset 0 plays). A note past the end is cut, with its release. Sanitized glide, decay and drive never produce NaN or leave `[−1, 1]` |
| AC6 | `plan_sound` | Trap has `Some(Sub808)` and the rest `None`. Plan JSON without `bass` reads as `None`; `"808"` round-trips |
| AC7 | `hits_until_next`, `accompany_take` | `round(onset·rate)` equals each `pattern_onsets` offset, and the last note ends at `len`. Over trap: the bass has the same rate, length and bars as the voice and drums; the sample at each kick offset is 0 and energy rises after it; `root_hz` is in `[40, 80)` and an octave of the grid root; the samples equal `render_808` at `plan.drive`. Over the other styles: `None` |
| AC8 | `build_song`, `playback_levels`, UI | The song has an `"808"` stem third, inside `span_bars`, and the mixdown contains it. `Σ levels·stems` equals the mixdown. The UI (browser check with a mocked shell): three sources start at one `at` through gain nodes set from `levels`; the generic beat still goes to the destination directly |
| AC9 | gates | fmt, clippy `-D warnings`, test, doc |

`pattern_onsets` also has its own tests:
- **Characterization:** `render_beat` is bit-identical before and after the
  refactor.
- **Edge cases:** empty for zero bars, zero rate or an empty pattern.
- **Order:** the offsets are non-decreasing.
- **Kick alignment:** each offset equals the sample where a kick hit begins in
  `render_beat`'s output.

## 7. Decision log

| Date | Decision | Rationale |
|------|----------|-----------|
| 2026-09-27 | Glide is linear in cents over `glide_secs` | It reaches its target exactly and is testable (the midpoint is the geometric mean). "Exponential glide" in the issue means exponential in Hz, which is this. |
| 2026-09-27 | Legato keeps the envelope, does not re-attack | A slide is one note moving, not two notes. |
| 2026-09-27 | `pattern_onsets` extracted from `render_beat` | One computation for where a kick lands, so the 808 cannot drift off it. |
| 2026-09-27 | A master gain mirrors export's peak limit in the UI | Three full-level loops otherwise clip the device. Export already scales the same way. |
| 2026-09-27 | `BassNote { hz, onset_secs, duration_secs }` instead of `QuantizedNote` | The voice reads three numbers. A caller building hits from sample offsets has no honest degree, octave or step to fill in (finding 5). |
| 2026-09-27 | The envelope belongs to the phrase; the glide starts from the current pitch | A per-note envelope clicked on short legato notes and never finished an attack interrupted mid-way. A glide from the previous target jumped when that note was cut mid-glide (findings 2 and 9). |
| 2026-09-27 | Onset and end are rounded from their own instants | `start + round(duration)` turned touching notes into a one-sample overlap at ordinary tempos (117 BPM at 44.1 kHz), so they glided instead of re-attacking (finding 3). |
| 2026-09-27 | Ties broken by `(start, hz, end)`, and settings sanitized | The render must not depend on list order, and no setting may produce NaN or leave `[−1, 1]` (findings 4 and 7). |
| 2026-09-27 | Playback levels computed in Rust and equal to the mixdown (owner decision) | The browser hears what export writes, the gates test it, and it applies to every style (finding 16). |
| 2026-09-27 | One kick pattern (`BeatVoiceSpec::pattern`) and one onset computation (`pattern_onsets`) | Where the kick lands and where the 808 hits must come from one definition (findings 10 and 11). |
